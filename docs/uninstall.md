# 卸载 WeChat Agent

从本机 Codex / Claude 或终端操作。不要让正在卸载的微信执行器删除自身，再期待它通过微信报告完成。当前没有 `uninstall` 命令；这是给用户与安装 agent 的清理流程，不会自动执行删除。

## 默认保留什么

默认只移除已确认属于该安装的程序、启动入口、skill 链接和后台服务，保留配置、浏览器资料、下载文件、运行记录及工作区。私有数据可能仍包含聊天、登录态和救援凭据，应留在本机并告知保留路径，不打印内容或上传。

即使用户要求清空本地运行数据，也要单独识别项目工作区。默认工作区位于安装根的 `watch/workspace`，自定义工作区可能在其他位置；不能通过删除整个安装根顺便删掉项目。Codex/Claude 的登录凭据和原生历史会话属于各自 CLI，不属于本项目的清理范围。

## 识别安装与停止进程

1. 读取启动入口和 `WECHAT_AGENT_HOME`，确认实际安装根。默认是 `~/.local/share/wechat-agent`；源码安装可能位于用户自己的 checkout。检查符号链接目标，不猜测路径，不递归追随链接删除其他目录。
2. 用该安装的 `bin/wechat-agent status` 或源码的 `npm run watch -- status` 检查状态。存在运行中或待处理任务时先报告，等待完成；取消需要用户明确选择，不强杀后重放。
3. 执行该安装的 `stop`。它停止 watch/执行器，保留浏览器；不能当作完整卸载。进程已崩溃或状态异常时，先核对实际 PID、命令路径和安装归属，再处理，不能只凭旧 PID 文件杀进程。
4. 在 watch 停止后关闭该安装专用的 Playwright 浏览器。正常关闭其专用窗口，或在确认控制端归属后使用现有本地控制接口的 `shutdown_browser` 动作。不要执行 `restart --browser`，它会重新启动。不要关闭日常 Chrome、微信桌面客户端或其他安装的浏览器。
5. 核实 supervisor、浏览器控制进程及其 AI 子进程已退出。独立的 Codex/Claude 会话必须保留；禁止用通用 `pkill node`、`pkill codex`、`pkill Chrome` 等清理。

## 移除程序、skill 和救援服务

- 一键安装通常产生 `app` 符号链接、`releases/`、`bin/wechat-agent`，以及可能存在的私人 `tools/`。只移除确认属于本安装且不再使用的文件；源码 checkout 有本地修改或用户文件时保留并报告。不要删除全局 Node、npm、Git、Codex、Claude 或共享 Playwright 浏览器缓存。
- 检查 `~/.codex/skills/wechat-agent` 和 `~/.claude/skills/wechat-agent`。安装器创建的是指向仓库 skill 的符号链接：核对目标后只解除该链接，不沿链接删除目标；独立复制或修改过的目录先确认归属，不整目录误删其他 skills。
- 若安装了救援心跳，检查实际 LaunchAgent 的 `Label`、`ProgramArguments` 和状态文件路径。当前安装器使用 `com.wechat-agent.rescue-heartbeat`，脚本及私有配置通常在 `~/.local/share/wechat-rescue`。旧安装可能不同，以文件和运行状态为准。确认该服务只属于本次卸载后，先卸载其 launchd job，再移除对应 plist 和程序。共享或其他安装在用的服务不得删除。
- 默认保留救援私有配置；只有用户明确清空数据且确认专属时才删除。Cloudflare Worker、D1、Access 应用和 DNS 不会随本机卸载消失。列出残留资源类型，云端删除需单独确认具体资源及是否被其他设备共用；不撤销共享凭据。

## 清空数据与验收

若用户明确要求删除本地数据，先列出精确目录及将保留的工作区，确认后再清理。若工作区嵌在待删除目录中，先保留或迁出工作区，不能直接删除父目录。默认 `watch/` 包含工作区和运行状态，不能整体当缓存处理。不要把凭据、浏览器资料或聊天备份到 Git 仓库。

完成后核实：已停止本安装进程；专用启动入口和 skill 链接已移除；已卸载的后台服务不会再次拉起；用户工作区和 CLI 凭据未被删除。报告保留的本地数据路径、仍保留的云端资源，以及无法确认的残留项。不要为了验证卸载重新启动 watch 或打开微信页面。
